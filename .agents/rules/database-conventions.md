# Database Conventions

## ORM
- **Drizzle ORM** for type-safe queries in `apps/api`
- Schema defined in `apps/api/src/db/schema.ts`
- Migrations managed via Supabase CLI in `supabase/migrations/`

## Naming
- **Tables**: `snake_case`, plural nouns (`contacts`, `deals`, `interactions`)
- **Columns**: `snake_case` (`first_name`, `created_at`, `tenant_id`)
- **Foreign keys**: `<referenced_entity_singular>_id` (`tenant_id`, `contact_id`, `deal_id`)
- **Indexes**: `idx_<table>_<column(s)>` (e.g., `idx_contacts_tenant_id`, `idx_deals_stage_id`)
- **Unique constraints**: `uq_<table>_<column(s)>` (e.g., `uq_phone_numbers_number`)
- **Check constraints**: `chk_<table>_<column>` (e.g., `chk_deals_priority`)

## Multi-Tenancy
- Every user-facing table MUST have `tenant_id UUID REFERENCES tenants(id) ON DELETE CASCADE`
- Row Level Security (RLS) policies enforce tenant isolation at the database level
- RLS policy pattern:
  ```sql
  CREATE POLICY "tenant_isolation" ON <table>
    FOR ALL
    USING (tenant_id = (auth.jwt() ->> 'tenant_id')::uuid);
  ```
- Never rely solely on application-level WHERE clauses for tenant filtering
- The `tenants` table itself does NOT have `tenant_id` — it IS the tenant

## Timestamps
- Always use `TIMESTAMPTZ` (never `TIMESTAMP` without timezone)
- All tables have `created_at TIMESTAMPTZ DEFAULT now()`
- Mutable tables also have `updated_at TIMESTAMPTZ DEFAULT now()`
- Use database triggers for auto-updating `updated_at`:
  ```sql
  CREATE TRIGGER set_updated_at
    BEFORE UPDATE ON <table>
    FOR EACH ROW
    EXECUTE FUNCTION update_updated_at_column();
  ```

## Primary Keys
- Use `UUID` primary keys generated by `gen_random_uuid()`
- Never use sequential integer IDs (prevents enumeration attacks)

## Soft Deletes
- Use `deleted_at TIMESTAMPTZ DEFAULT NULL` for soft-deletable entities
- RLS policies should include `AND deleted_at IS NULL` in the USING clause
- Hard deletes only for webhook_logs (retention-based cleanup)

## JSON Columns
- Use `JSONB` (not `JSON`) for structured metadata
- Always provide a default: `DEFAULT '{}'::jsonb` or `DEFAULT '[]'::jsonb`
- Document the expected shape in a comment above the column
- Validate JSONB structure at the application layer with Zod

## Array Columns
- Use PostgreSQL native arrays for simple lists: `tags TEXT[] DEFAULT '{}'`
- For complex arrays, prefer JSONB

## Migration Workflow
1. Create migration: `npx supabase migration new <descriptive_name>`
2. Write SQL in the generated timestamped file
3. Test locally: `npx supabase db reset`
4. Review: Ensure migration is reversible (include comments for rollback)
5. Push to staging: `npx supabase db push --linked`
6. CI/CD auto-applies on merge to `main`

## Seed Data
- Development seed data in `supabase/seed.sql`
- Seed creates a demo tenant with realistic sample data
- Seed is idempotent (safe to run multiple times)

## Performance
- Index all foreign key columns
- Index columns used in WHERE clauses and ORDER BY
- Use `EXPLAIN ANALYZE` for queries returning >1000 rows
- Limit default page size to 25 rows
